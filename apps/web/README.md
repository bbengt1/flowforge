# `@flowforge/web`

Next.js App Router UI for FlowForge. Compose builds this image with `context: ./apps/web`. Local and stack startup are documented in the repository root `README.md` and `docs/deployment.md`.

The production image runs as UID/GID `65532` (same as `apps/api`). Compose adds a read-only root filesystem, tmpfs, dropped capabilities, `no-new-privileges`, and resource limits. Responses include the E1.3 secure-header set (`apps/web/src/lib/security-headers.ts`); HSTS is omitted on `http://localhost:3000`.

`/membership` is the E2.1 / E2.3 operator UI (Chloe). `/isolation` is the E2.2 negative isolation exercise (also embedded on `/membership`). `/workflows` is the E3.1 YAML validate/normalize operator, the E3.2 draft/publish/history operator, and the E3.3 core-neutral node palette/inspector (catalog is `phase: core` only; the action palette places the seven E3.3 types and never treats triggers as graph nodes; run requires a published `workflowVersionId`). `/credentials` is the E4.1 encrypted vault operator stacked on jonny's #38 routes (catalog, list, create, detail, rotate/disable/enable/test/use, usage, events, deletion-impact, DELETE `{confirm:true}`), densified for R5.1 (#264 / Part of #231 — **keep #264 open**) display-name find (search/filter, useful columns, open-to-detail). Vault create/rotate send `secret` once and clear it; responses are sanitized so unexpected plaintext is stripped. Search is client-side on display name/tags only — `GET /credentials` has no query params. The UI never reads `CREDENTIAL_KEK`. `/config` is the E4.2 versioned operational-config operator stacked on the #41 map on main (targets, profiles, connections, templates, schemas, policies): PUT draft with body `revision`, POST select for pins, no authorized/compare/restore routes. Browser session calls use same-origin `/api/v1/*` (`credentials: include`) so `ff_session` / `ff_csrf` (`Path=/api/v1`) are sent. Those paths rewrite to `/api/control-plane/*`. CSRF (`X-CSRF-Token`) is required on mutations when a cookie session is present; header-only local-dev fallback skips CSRF. Workspace lookup is tenant + workbench key, never a host-supplied workspace UUID. Bearer tokens and credential plaintext are never stored in `localStorage` or the URL. `/embed/v1` is the E11.1 embed mount (Chloe): Next rewrites those hrefs onto the canonical pages. Host frontends `POST /embed/exchange` `{assertion}` (body only) for `ff_session` / `ff_csrf`. `GET /embed/catalog` and `GET /embed/jwks` are public; mint stays host-backend. Assertion tokens are never put in the URL or `localStorage`. Paths live in `src/lib/embed-contract.ts` (`e112-#127`). E11.2 chrome + deep links honor FlowForge-verified `(tenant_id, workbench_key)` / `session.embed` after exchange (`src/lib/embed-tenancy-contract.ts`); later API calls send `embedWorkspaceHeaders`. Host query values never authorize. Relates to #122 / Part of #120 — keep #122 open. `/portal/workflows` is the E11.3 CP Ops Portal host (Chloe) on jonny's #129 map (`e113-#129`): Portal entry RBAC is host-only; `GET /api/v1/portal/adapter` maps roles; mint is `POST /api/v1/portal/adapter/assertions` `{portalRoles}`; iframe mounts `/embed/v1` with display-only tenant/workbench; assertion is postMessaged and forgotten so the embed shell `POST /embed/exchange`. Adapter: `src/lib/portal-adapter-contract.ts`. Relates to #123 / Part of #120 — keep #123 open.
