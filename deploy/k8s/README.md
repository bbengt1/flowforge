# Kubernetes foundation

Apply with:

```bash
kubectl apply -k deploy/k8s
```

Replace before any real environment:

- `ghcr.io/bbengt1/flowforge-api:foundation` with a **digest-pinned** image
- `ghcr.io/bbengt1/flowforge-web:foundation` (built from `apps/web/Dockerfile`, repo-root context) with a **digest-pinned** image. Rebuild with `NEXT_PUBLIC_API_URL` set to the public https API origin. The Deployment sets `API_INTERNAL_URL=http://flowforge-api:8080` and the same public origin for server-rendered links. Do not copy compose localhost URLs.
- `ghcr.io/bbengt1/flowforge-script-runner:foundation` (built from `apps/api/Dockerfile.script-runner`) with the runtime-profile digest. The runner creates Jobs from `deploy/kubernetes/script-runner-deployment.yaml` only when `CONTROL_PLANE_API_CIDR` is set on the ConfigMap and both NetworkPolicies below are applied with that CIDR. See [deployment.md](../../docs/deployment.md#script-runner-image).
- `deploy/kubernetes/script-runner-networkpolicy.yaml` and `deploy/k8s/runner-controlplane-networkpolicy.yaml` via `envsubst '${CONTROL_PLANE_API_CIDR}'` (not part of `kubectl apply -k`; a world CIDR is forbidden). The runner refuses script Jobs when the CIDR or the live script policy is missing. `SCRIPT_RUNNER_SKIP_NETWORK_POLICY` is refused on this production-locked runner.
- `api.example.com`, `app.example.com`, and the `flowforge-tls` secret (or enable cert-manager). The secret must cover both hosts. Ingress sends `app.example.com` to `flowforge-web:3000`.
- `deploy/k8s/api-secret.example.yaml` with a real `DATABASE_URL` (external secrets / sealed secrets), `KMS_PROVIDER` plus `CREDENTIAL_KEK_WRAPPED` (plaintext `CREDENTIAL_KEK` is a **boot-fail**), `EMBED_SIGNING_KEY`, `JOB_BINDING_SECRET`, `SCRIPT_SIGNING_KEY` (missing/malformed HMAC keys are a **boot-fail**), and `ARTIFACT_S3_ACCESS_KEY_ID` / `ARTIFACT_S3_SECRET_ACCESS_KEY` plus `ARTIFACT_S3_BUCKET` on the ConfigMap (missing S3 settings are a **boot-fail**; do not copy compose MinIO credentials; do not set `ARTIFACT_S3_CREATE_BUCKET`)
- Database egress if PostgreSQL is not a pod labeled `app.kubernetes.io/component=postgres` in this namespace

The web Deployment (`flowforge-web`) runs `node apps/web/server.js` as UID 65532 with a read-only root, dropped capabilities, and `emptyDir` volumes on `/tmp` and `/app/apps/web/.next/cache`. Kubelet probes `GET /` on port 3000: the Next app has no process-local health route, and `/api/control-plane/health` proxies the Go API. The web NetworkPolicy allows ingress from `ingress-nginx` to port 3000 and egress only to API pods on 8080 plus cluster DNS. Compose `/usr/local/bin/worker` is not in this directory. Production claims stay on `/usr/local/bin/runner` (`runner-deployment.yaml`).

## Multi-replica HA

API, web, and runner Deployments set `replicas: 2`. Each has a PodDisruptionBudget (`maxUnavailable: 1`), a HorizontalPodAutoscaler (minimum 2; API max 6, web max 4, runner max 4, CPU 70%), and preferred pod anti-affinity on `kubernetes.io/hostname`. A single-node cluster can still schedule both pods. Rolling updates use `maxUnavailable: 0` and `maxSurge: 1`. `kubectl apply` of a Deployment resets the live count to 2; the HPA owns the count between applies.

`JOB_BINDING_SECRET` and `SCRIPT_SIGNING_KEY` are the shared `flowforge-api` Secret on every API and runner replica. The process boot-fails if either is missing or malformed. It does not mint a per-pod key. A ticket or script signature from one replica verifies on the others. Fencing tokens and leases stay in PostgreSQL. Runner `WORKER_ID` is the pod name, so two replicas are distinct fence holders. A different worker id or a stale token fails closed.

`FLOWFORGE_REPLICAS` on the API container is `2`, which covers Deployment `replicas` and the HPA `minReplicas`. Above 1 the process boot-fails when a session, JTI, lockout, vault, workflow, or artifact backend is in-memory or pod-local (`memory` or `filesystem`). Postgres and S3 stay. Services do not set `sessionAffinity`. In-process login and embed rate limits are not this guard.

Graceful drain: API and web run `preStop` `sleep 15` so in-flight requests can finish after the pod leaves the Service endpoints, then `terminationGracePeriodSeconds: 45`. The API ConfigMap sets `SHUTDOWN_TIMEOUT=25s`. On SIGTERM the API resigns scheduler leadership (unlocks advisory lock `881726402` on a live context) before HTTP shutdown. The runner has no Service; `terminationGracePeriodSeconds: 40` and `WORKER_DRAIN_TIMEOUT=30s` finish the in-flight claim and do not start another. A claim that outlives the budget is left for lease recovery.

Size Postgres `max_connections` for `(6 + 4) × 8` application connections (the per-pod pool cap) plus backup and admin headroom. Do not lower replicas below 2.

The API process also applies forward-only migrations on connect. With `SCHEDULER_ENABLED=true` (ConfigMap default) one replica holds advisory lock `881726402` and ticks schedule dispatch, lease recovery, and retention purge (`SCHEDULER_INTERVAL`, default `30s`). Other replicas do not tick. Set the flag to `false` to opt out. That loop does not run encrypted backups — those are `flowforge-db-backup` (`backup-cronjob.yaml`, daily `0 2 * * *` UTC, image `ghcr.io/bbengt1/flowforge-backup:foundation` from `scripts/backup/Dockerfile`). Apply `backup-secret.example.yaml` (DSN, `BACKUP_ENCRYPTION_KEY`, `BACKUP_S3_*`) and open allowlisted object-store egress on the backup NetworkPolicy before production. Ciphertext lands under `flowforge-db/` in `BACKUP_S3_BUCKET`, not the artifact `{tenant}/{workspace}/{ref}` layout. Postgres NetworkPolicy already admits the `backup` component. RPO 24h / RTO gate: [retention and backup](../../docs/operations/retention-backup.md). Production TLS is terminated at Ingress; the API ConfigMap sets `APP_ENV=production`, `REQUIRE_TLS=true`, and `TRUSTED_PROXY_CIDRS` for the cluster ranges. Do not set `TRUSTED_DEV_IDENTITY_HEADERS` or `SEED_LOCAL_DEFAULTS` on this ConfigMap (the process refuses to start if those flags are combined with production or TLS). Set a unique PKCS#8 `EMBED_SIGNING_KEY` on the Secret — missing signing material is a **boot-fail** in production (ADV-006); do not copy the compose local key. Set unique `JOB_BINDING_SECRET` and `SCRIPT_SIGNING_KEY` (32-byte base64 or 64 hex) — missing or malformed values are a **boot-fail**; the process never mints a per-process random HMAC key. If you set `EMBED_OVERLAP_KEYS`, every key requires `overlapUntil` (RFC3339, max 4h) or the process boot-fails (ADV-014). Set explicit `EMBED_ISSUER` / `EMBED_ISSUER_ALLOWLIST` and `PORTAL_ISSUER` / `PORTAL_ISSUER_ALLOWLIST`; empty lists fail closed at request time (`403` on mint/exchange) and must not be copied from compose local seeds. Every production issuer must be an absolute `https://` URI (ADV-018); `http://` is a boot-fail. HTTP liveness/readiness probes to `/api/v1/health` and `/api/v1/readiness` are exempt from that TLS requirement so kubelet can reach the pod directly. Those probe paths stay unauthenticated. Build the API image with `--build-arg BUILD_SHA=<git sha>` (and optional `BUILD_VERSION`) so `/api/v1/health` reports which binary is running; missing values stay `unknown` / `dev` and do not fail the probe. Optional ConfigMap `STATEMENT_TIMEOUT` / `LOCK_TIMEOUT` override the application-pool checkout defaults (`15s` / `5s`). `GET /api/v1/metrics` and OpenAPI/swagger require `platform.administer` (`PLATFORM_ADMINS`) — scrapers send `Authorization: Bearer` with an `ff_session` token (see [deployment](../../docs/deployment.md)). Operator OpenAPI, incident/recovery, and retention/backup: [operations](../../docs/operations/index.md).
